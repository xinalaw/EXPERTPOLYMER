# Expert Polymer — frontend

Vue 3, TypeScript и Vue Router. Node.js 22.12+ (ветка 22), 24 или 26+.

## Весь проект через Docker

Из корня репозитория, без локальных Node.js и Python:

```sh
./scripts/docker-up.sh --mock
```

Это лёгкий запуск frontend, API с админ-панелью, PostgreSQL, Redis и Celery
без torch. Полный ML-режим: `docker compose up -d --build --wait`.
Весь интерфейс доступен на http://localhost:5173, Swagger — на
http://localhost:8000/docs. Frontend использует `API_PROXY_TARGET=http://backend:8000`
и пустой `VITE_API_URL`, поэтому `/api` и `/static` идут через Vite.
`npm ci` выполняется при сборке образа и кэшируется по lock-файлу;
после изменения исходников повторите команду запуска для пересборки.

Первого администратора создайте по инструкции в [корневом README](../README.md).
Остановка: `docker compose down`; БД, очередь и изображения сохраняются.

## Локальный запуск frontend

Из папки `frontend/`:

```sh
npm ci
npm run dev
```

Открыть http://localhost:5173. Backend должен работать на порту 8000.
Vite проксирует `/api` и `/static`; в Docker цель прокси — `http://backend:8000`.
Команды Windows при запрете PowerShell-скриптов: `npm.cmd` вместо `npm`.

Frontend работает с существующими `/api/auth/login` и `/api/auth/me`.
Изменять backend для запуска интерфейса не требуется.
Администратору доступна панель `/#/admin` из основного меню; роли проверяются
и маршрутизатором, и backend API.

## Архитектура

- `src/api/` — типизированный API, отмена и таймауты запросов, разбор ошибок.
- `src/stores/` — общее состояние сессии и локальных настроек.
- `src/composables/` — черновик анализа и загрузка истории.
- `src/components/ui/` — поля формы, диалог, изображения и сетка карточек.
- `src/components/analysis/` — загрузчик и общая визуализация результатов.
- `src/components/admin/` — управление пользователями, анализами, задачами,
  инвайтами и журналом администратора.
- `src/router.ts` — ленивые страницы и проверки доступа.
- `src/styles/main.css` — дизайн-токены и общие стили.

Маршруты используют hash (`/#/history`): работают прямые ссылки,
обновление страницы и история браузера без правил SPA rewrite на сервере.
Дата и номер страницы истории сохраняются в URL. Наличие следующей страницы
определяется дополнительной записью в ответе API; вымышленного total нет.

Черновик и результат анализа сохраняются при переходах внутри приложения,
но сбрасываются при смене пользователя и обновлении вкладки. Анализ идёт
одним синхронным запросом, поэтому индикатор не показывает вымышленные
проценты. Остановка ожидания не отменяет серверную задачу. История позволяет
проверить, сохранился ли результат после таймаута или перезагрузки.

## Проверки

```sh
npm run check
npm run format:check
npx playwright install chromium
npm run test:e2e
```

`check` запускает проверку форматирования, линтер, unit/component-тесты и сборку с проверкой типов.
Браузерные тесты проверяют desktop и mobile, клавиатуру, скачивание,
пагинацию, формы и доступность через axe. Они используют изолированные
API-ответы с проверкой Bearer-токена и не создают пользователей и анализы в рабочей базе.
Отдельно проверяются регистрация, выход между вкладками, истечение сессии,
ошибка загрузки профиля и работа при запрете браузерного хранилища.

Можно использовать установленный Chrome, задав `PLAYWRIGHT_CHANNEL=chrome`.
По умолчанию тест сам запускает сервер на 127.0.0.1:5173; порт должен быть свободен.
Для уже запущенного тестового сервера задайте `PLAYWRIGHT_REUSE_SERVER=1`.
Скриншоты и трассы лежат в игнорируемой папке `test-results/`.

## Сборка и размещение

```sh
npm run build
```

Файлы `dist/` раздаёт статический сервер. Разместите frontend и API за одним
origin: `/api` и `/static` должны проксироваться на FastAPI. Сам FastAPI сейчас
не раздаёт `dist/`. Dev-прокси Vite в production не работает.

Параметры frontend:

- `VITE_API_URL`: пусто для same-origin либо абсолютный адрес API, заданный
  при сборке.
- `API_PROXY_TARGET`: цель dev-прокси; по умолчанию http://localhost:8000.
  Читается из `.env` и `.env.[mode]`; переменная окружения процесса имеет приоритет.

Токен доступа активируется после успешной проверки профиля и хранится в `sessionStorage`;
опция «Запомнить меня» переносит его в `localStorage`. Выход из сохранённой сессии
синхронизируется между вкладками. Если хранилище недоступно, вход работает в памяти
до перезагрузки вкладки. При истечении сессии токен удаляется из памяти и хранилищ.
Это ограничение существующего backend API: HttpOnly-cookie
может установить только сервер. Не вставляйте на страницу сторонние скрипты и
задайте строгую Content Security Policy на production-сервере.

## Реальные возможности

- JPG, PNG, TIFF, BMP до 20 МБ; проверяются расширение, MIME и сигнатура.
  Финальную проверку возможности обработки делает backend. TIFF может не
  отображаться в браузере, но допускается к анализу.
- Отчёт JSON доступен и на странице результата, и в истории.
- Профиль отображает серверные данные. Редактирование профиля не заявляется,
  поскольку такого endpoint нет.
- Настройки уменьшают анимацию и задают размер страницы истории.
- Контакты подготавливают mailto-письмо или скачиваемый текстовый черновик.
  Автоматической отправки нет: почтовый сервис в проекте не настроен.
- Отсутствующие экспертные данные явно отмечаются; интерфейс не приписывает
  этому конкретную причину или качество модели.
